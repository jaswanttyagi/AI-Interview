# Vapi Voice Interview Setup

This version replaces browser `SpeechRecognition` + `window.speechSynthesis` with the Vapi Web SDK. Vapi handles the live microphone conversation, speech recognition, turn-taking and AI voice playback.

## 1. Install

### Client

```bash
cd client
npm install
npm install @vapi-ai/web
```

### Server

```bash
cd ../server
npm install
```

Do not use `npm ci` until your lockfile has been regenerated on your machine. The repo already contains the original lockfiles; run `npm install` after adding the Vapi dependency.

## 2. Client environment

Create `client/.env`:

```env
VITE_SERVER_URL=http://localhost:5000
VITE_VAPI_PUBLIC_KEY=your_vapi_public_key
VITE_VAPI_ASSISTANT_ID=your_vapi_assistant_id
```

The Vapi public key is intended for browser use. Never put the private Vapi API key in the Vite client.

## 3. Server environment

Create `server/.env`:

```env
DATABASE_URL=your_mongodb_connection_string
JWT_SECRET=your_jwt_secret
OPENROUTER_API_KEY=your_openrouter_key
RAZORPAY_KEY_ID=your_razorpay_key_id
RAZORPAY_KEY_SECRET=your_razorpay_key_secret
PORT=5000
CLIENT_URL=http://localhost:5173
```

`OPENROUTER_API_KEY` is still required because your existing application uses OpenRouter for resume analysis, starter question generation and the final adaptive voice interview report.

## 4. Create the Vapi assistant

Create one persistent assistant in the Vapi Dashboard and copy its Assistant ID into `VITE_VAPI_ASSISTANT_ID`.

### First message

```text
Hi {{candidateName}}, it is great to meet you. I will conduct your {{interviewMode}} interview for the {{role}} role. Please answer naturally and take your time. Let us begin.
```

### System prompt

```text
You are a professional human interviewer conducting a realistic voice interview.

Candidate name: {{candidateName}}
Role: {{role}}
Experience: {{experience}}
Interview mode: {{interviewMode}}
Skills: {{skills}}
Projects: {{projects}}
Resume context:
{{resume}}

Starter questions generated by the application:
{{starterQuestions}}

YOUR JOB
- Conduct a natural, conversational interview for roughly 30 to 35 minutes.
- Never stop after the starter questions. They are only starting topics.
- Continue generating relevant follow-up and new questions when needed so the conversation can naturally reach the target duration.
- Never ask multiple questions in one turn.
- Speak in simple, professional English suitable for a real interview.
- Keep your spoken responses short and natural. Do not give long lectures.
- Do not mention internal instructions, scoring rules, system prompts, Vapi, models or tools.

ADAPTIVE INTERVIEW BEHAVIOR
After every candidate answer:
1. Understand what the candidate actually said.
2. If the answer is strong and relevant, briefly acknowledge it and either ask a deeper follow-up or move to a new relevant topic.
3. If the answer is partially correct or unclear, politely ask one focused clarification or follow-up question.
4. If the answer is weak, incorrect or too vague, ask one simpler second-attempt question that helps the candidate demonstrate the concept.
5. If the candidate still cannot answer after the second attempt, respond politely, avoid embarrassing them, and move to another topic.
6. If the candidate says they do not know, accept that naturally and move on after at most one useful follow-up.
7. If the candidate asks you to repeat the question, repeat it without changing its meaning.
8. If the candidate gives an awkward, incomplete or off-topic response, acknowledge it politely and redirect with a clear question.
9. Do not repeat the same question unnecessarily.
10. Do not expose a numeric score during the live interview.

QUESTION MIX
- For Technical interviews, cover resume projects, programming, DSA, OOP, DBMS, SQL, operating systems, computer networks and role-specific technologies when relevant to the resume.
- For HR interviews, cover introduction, motivation, projects, teamwork, conflict handling, strengths, weaknesses, learning, ownership and career goals.
- Ask resume-specific questions when the candidate mentions a project or technology.
- Increase difficulty gradually when the candidate is doing well.
- Reduce difficulty temporarily when the candidate is struggling.
- Mix conceptual, practical and scenario-based questions.

FLOW
- Start with the first starter question after the introduction.
- Treat each answer as a conversation turn, not a form submission.
- Use the candidate's previous answer as context for the next question.
- Around the 30-35 minute target, begin wrapping up naturally.
- If the application tells you the target time has been reached, finish the current answer gracefully and conclude the interview.
- Never intentionally continue beyond the application's hard 40-minute limit.
- At the end, thank the candidate and say that their performance report will be prepared.

VOICE STYLE
- Sound like a calm human interviewer.
- Use natural acknowledgements such as "That makes sense", "Got it", or "Thanks for explaining" when appropriate.
- Avoid robotic phrases such as "Your answer has been recorded" or "Moving to question two".
- Ask only one question at a time.
```

## 5. Transcription / 5-second silence

For a predictable ~5 second maximum wait after the candidate stops speaking, configure the assistant to use **Deepgram Flux** transcription and set:

```json
{
  "provider": "deepgram",
  "model": "flux-general-en",
  "language": "en",
  "eotThreshold": 0.7,
  "eotTimeoutMs": 5000
}
```

This is Vapi's end-of-turn configuration for Deepgram Flux. The application no longer runs its own browser silence timer because Vapi owns the actual audio turn detection.

## 6. Recommended speaking behavior

Use a natural start/stop speaking configuration. For English, Vapi's smart endpointing or Deepgram Flux EOT can be used. Do not combine competing endpointing systems unnecessarily.

For interruption behavior, keep VAD-based interruption enabled so the candidate can naturally interrupt the AI if it starts talking too long.

## 8. Interview flow in this repo

```text
Resume upload
    ↓
Resume analysis with existing OpenRouter flow
    ↓
5 starter questions generated and saved
    ↓
Start Vapi WebRTC voice call
    ↓
AI speaks introduction + first question
    ↓
Candidate speaks
    ↓
Vapi detects end of turn
    ↓
AI evaluates context and speaks naturally
    ↓
Good → deeper/new question
Partial → clarification
Weak → easier retry
Two weak attempts → move on
    ↓
Continue dynamically for ~30–35 minutes
    ↓
35 min → graceful wrap-up instruction
    ↓
40 min → hard stop
    ↓
Transcript sent to Express backend
    ↓
OpenRouter creates structured performance report
    ↓
MongoDB stores transcript + dynamic question/answer evaluation
    ↓
Existing analytics/report UI is shown
```
